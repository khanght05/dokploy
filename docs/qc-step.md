# Bước QC khi deploy (test plan + test tự sinh)

Tài liệu cho người vận hành Dokploy của fork này. Phần dựng service QC nằm ở `DEPLOY-SERVICE.md` trong repo **QC_Agent_Tool**; phần mô tả mã nguồn nằm ở mục "QC step" của `CLAUDE.md`.

## 1. Bước QC làm gì

Mỗi application có thể **bật** bước QC (mặc định tắt). Khi bật, mỗi lần Deploy:

```
clone repo ─▶ QC step ─▶ (tùy chọn) chạy test ─▶ build ─▶ deploy
              │            │
              │            └ test do service sinh, chạy trong container tạm trên server build
              └ gọi QC service: tạo hoặc cập nhật test plan cho đúng commit vừa clone
```

- **Test plan**: tài liệu mô tả các kịch bản cần test, lưu trên application (tab **Test Plan**). Mỗi lần ra bản mới, bản cũ được giữ lại trong card **History** (tối đa 100 bản mỗi application).
- **Test sinh ra**: service viết test (Node, Python hoặc Go) từ plan. **Dokploy là bên chạy test**, không phải service.
- **Phân loại lỗi**: nếu test fail, service dùng AI phân loại từng lỗi (lỗi ứng dụng, test viết sai, flaky, môi trường) và tạo báo cáo.

Application không bật QC **không bị đổi hành vi**: không gọi service, không ghi trường QC lên deployment.

## 2. Điều kiện cần

| Cần | Chi tiết |
|---|---|
| QC service đang chạy | Dựng theo `DEPLOY-SERVICE.md` của QC_Agent_Tool. Kiểm tra bằng `GET <url>/healthz` (kỳ vọng `status: ok`) |
| Mạng | Dokploy gọi được service qua HTTP(S). Nếu dùng webhook, service gọi ngược được Dokploy |
| Key | `QC_SERVICE_API_KEY` của Dokploy trùng `QC_SERVICE_API_KEY` (hoặc `_NEXT`) của service |
| Docker trên server build | Cần khi bật test sinh: Dokploy kéo image runner (mặc định `node:22`, `python:3.12`, `golang:1.23`) |
| Nguồn mã | **GitHub** hoặc **Git** (URL tùy chỉnh). Nguồn khác (GitLab, Gitea, Bitbucket, Docker, Drop) bị bỏ qua, kèm lý do ở log deployment |

## 3. Cấu hình (biến môi trường của Dokploy)

| Biến | Ý nghĩa |
|---|---|
| `QC_SERVICE_BASE_URL` | URL của service, ví dụ `https://qc.company.com`. **Để trống thì bước QC không chạy được** |
| `QC_SERVICE_API_KEY` | Key Bearer gửi cho service |
| `QC_SERVICE_TIMEOUT_SECONDS` | Dokploy chờ một run tối đa bao lâu (mặc định 900). Repo lớn hoặc test nhiều cần cao hơn, ví dụ 1500 |
| `QC_SERVICE_CALLBACK_URL` | Tùy chọn. `https://<dokploy>/api/qc/webhook`; service báo run xong qua đây thay vì chỉ để Dokploy poll |
| `QC_SERVICE_WEBHOOK_SECRET` | Tùy chọn. **Phải giống** `QC_SERVICE_WEBHOOK_SECRET` của service. Chữ ký HMAC-SHA256 có timestamp |

Webhook chỉ là tín hiệu đánh thức: thiếu, trễ hoặc bị từ chối đều **không ảnh hưởng kết quả**, vì Dokploy vẫn poll để lấy trạng thái.

## 4. Migration

Bản này thêm migration `0197` đến `0201` (cột QC trên `application` và `deployment`, bảng `test_plan_history`). Tất cả chỉ **thêm**, cột mới có giá trị mặc định hoặc cho phép null; không đổi dữ liệu cũ. Bản `0201` còn chép test plan hiện có vào bảng lịch sử.

Bản chạy production (`pnpm start` hoặc image Docker) **tự chạy migration khi khởi động** (`dist/migration.mjs` chạy trước `dist/server.mjs`), nên bình thường không cần làm gì thêm. Môi trường phát triển phải chạy tay: `pnpm --filter=dokploy run migration:run`.

Migration là **bắt buộc**: mã mới đọc các cột mới của bảng `application` ở mọi truy vấn, nên nếu chạy mã mới trên DB chưa migrate thì thao tác với application sẽ lỗi, không chỉ riêng phần QC.

## 5. Bật cho một application

**Application → Advanced → QC & Test Automation**

| Mục | Ý nghĩa | Mặc định |
|---|---|---|
| QC test-plan step | Bật bước QC cho application này | Tắt |
| If the QC service errors or times out | `Skip & continue deploy` (open) hoặc `Block deploy` (closed) cho lỗi của chính bước plan | open |
| Run tests before deploy | Chạy test trước khi bản mới thay bản đang chạy | Tắt |
| Which tests | `My own test command, inside the built image` hoặc `Tests generated by the QC service` | command |
| Test command | Chỉ với "my own test command" | trống |
| Test runner image | Chỉ với test sinh: để trống thì chọn theo ngôn ngữ dự án | trống |
| If tests fail | `Block deploy` hoặc `Warn & continue deploy` | Block |

**Test sinh ra** cần QC step đã bật và nguồn GitHub/Git. Chúng chạy trong container tạm với: bản sao mã nguồn, **không có biến môi trường của app**, không Docker socket, bỏ toàn bộ capability, giới hạn 2 GB RAM, 2 CPU, 512 tiến trình và thời gian của manifest. Mạng bị tắt trừ khi bộ test cần để cài gói.

## 6. Khi nào một deploy bị chặn

| Tình huống | Kết quả |
|---|---|
| Bước plan lỗi hoặc quá thời gian, policy **open** | Ghi cảnh báo vào log, deploy tiếp |
| Bước plan lỗi hoặc quá thời gian, policy **closed** | Deploy dừng; lý do ghi ở log deployment |
| Test fail và AI xếp là **lỗi ứng dụng** (`verdict: fail`), policy **Block** | Deploy dừng |
| Test fail nhưng AI xếp là test sai, flaky hoặc môi trường (`verdict: warn`) | **Không bao giờ chặn.** Deployment ghi `failed` kèm phân loại và để deploy tiếp |
| Không chạy được test (service lỗi, không tải được bộ test), policy **Block** | Deploy dừng |
| Mọi test pass (`verdict: pass`) | Deploy tiếp |

Các deploy của **cùng một application** không chạy song song bước QC: lần sau chờ lần trước (khóa `testPlanStatus`). Deploy của application khác không phải chờ nhau, nhưng hàng đợi build của Dokploy mặc định chạy **1 build một lúc** (Settings → Builds concurrency).

## 7. Nơi xem kết quả

- **Tab Test Plan**: plan hiện tại, trạng thái (`generating`, `ready`, `error`), nút **Regenerate** (lập lại plan cho commit đang chạy, chạy nền) và card **History**.
- **Tab Deployments**: badge cho từng deployment (bản plan, kết quả test, phân loại lỗi) và nút **Report** mở báo cáo gần toàn màn hình. Báo cáo chạy trong iframe `sandbox`.
- **Log deployment**: các dòng `== QC test plan v.. ready ==`, `== QC generated tests: ... ==` và lý do khi bị chặn hoặc bỏ qua.

Cùng một commit thì service **dùng lại** plan và bộ test cũ (không tốn tiền). Một commit chỉ đổi file CI, lockfile, ảnh hoặc giấy phép cũng được coi là không đổi.

## 8. Chi phí

Chi phí do service tính từ token và bảng giá model (xem `DEPLOY-SERVICE.md`, mục Chi phí). Mặc định: tối đa $1 mỗi run và $20 mỗi ngày. Tham khảo đo thật trên repo mẫu nhỏ: plan khoảng $0.07, sinh test khoảng $0.02, phân loại khoảng $0.01 (cả lượt khoảng $0.10).

## 9. Tắt hoặc gỡ

- **Một application**: tắt "QC test-plan step" trong Advanced. Deploy trở về như cũ ngay.
- **Toàn bộ**: để trống `QC_SERVICE_BASE_URL`. Application nào còn bật QC sẽ ghi lỗi ở bước plan và xử lý theo policy của nó (open thì vẫn deploy).
- Quay về bản cũ: các cột và bảng mới là phần thêm, mã bản cũ không đọc chúng nên có thể chạy lại trên DB đã migrate mà không cần rollback migration. Tôi chưa thử quay lại thật.

## 10. Sự cố thường gặp

| Hiện tượng | Nguyên nhân và cách xử lý |
|---|---|
| Plan luôn `error` ngay lập tức | `QC_SERVICE_BASE_URL` trống, sai URL, hoặc `QC_SERVICE_API_KEY` không khớp (service trả 401) |
| `generating` kéo dài | Một lần chạy trước bị ngắt. Khi Dokploy khởi động lại, các plan kẹt được đặt thành `error`; còn không thì quá `QC_SERVICE_TIMEOUT_SECONDS` + 60 giây được coi là quá hạn và có thể chạy lại |
| Bấm Regenerate báo đang chạy | Một run khác (deploy hoặc Regenerate) đang giữ khóa của application này |
| Test sinh bị bỏ qua | Cần QC step đã bật và nguồn GitHub/Git; xem dòng `QC generated tests skipped` ở log |
| `Could not pull` image runner | Server build chưa có mạng ra registry, hoặc `Test runner image` sai |
| Test fail nhưng deploy vẫn chạy | Verdict là `warn` (AI xếp không phải lỗi ứng dụng). Mở Report để xem lý do |
| Deploy hai app không chạy song song | Builds concurrency đang là 1; tăng ở Settings nếu máy đủ mạnh |
